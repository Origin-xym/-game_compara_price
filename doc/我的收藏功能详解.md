## 一、一句话链路

「我的收藏」页 → `GET /api/favorites?page=1&size=12` → 拦截器把 token 解成 `userId` 塞进 `UserContext` → `FavoriteServiceImpl.list()` 用 `selectMyPage`（SQL 里 JOIN `game.status=1`）取当页收藏 → 再批量取类型名与**当前价**（复用列表页同一段 SQL）→ 逐条组装 `FavoriteItemVO`（封面/最低价/平台标签/有效折扣/收藏时间）→ `PageResult` 统一分页壳返回 → 前端 `FavoriteList.vue` 用 3:4 封面网格渲染 + "共 N 款" + 分页器；取消收藏走 `DELETE` 后重拉当页（必要时页码回退一格）。

## 二、用到的接口

| 接口 | 谁调 | 作用 | 关键返回 |
| --- | --- | --- | --- |
| `GET /api/favorites?page=1&size=12` | 收藏页加载、翻页 | **本功能主接口** | `PageResult<FavoriteItemVO>` |
| `DELETE /api/favorites/{gameId}` | 收藏页"取消收藏" | 物理删除该用户该游戏 | `null` |
| `GET /api/favorites/{gameId}/exists` | 详情页 | 按钮是不是"已收藏" | `{favorited:bool}` |
| `POST /api/favorites/{gameId}` | 详情页 | 收藏（幂等） | `null` |

下文只讲前两个（后两个是"收藏/取消"入口，已在上一轮讲过）。四个接口全在 `WebMvcConfig.java` 第 58 行的 `/favorites/**` 拦截范围内，**未登录一律 40100**。

主接口返回体（`Result` 外层 + `PageResult` 内层，字段名由 getter 决定）：

```
{ "code":0, "message":"ok",
  "data": {
    "total":3, "page":1, "size":12,
    "list":[ { "favoriteId":11, "gameId":9, "name":"赛博朋克 2077",
               "coverUrl":"https://…", "gameTypeName":"角色扮演",
               "hasQuote":true, "minPriceCny":22.00, "platformCount":2,
               "platforms":[{"platformId":9,"code":"STEAM","name":"Steam"},
                            {"platformId":11,"code":"XIAOHEIHE","name":"小黑盒"}],
               "discountActive":false, "maxDiscountRate":null,
               "favoriteTime":"2026-11-24T20:15:30" } ],
    "totalPages":1, "hasMore":false } }
```

`totalPages` 与 `hasMore` 不是字段，而是 `PageResult` 第 131–142 行的两个 getter（`getTotalPages()`、`isHasMore()`），Jackson 自动序列化出来，前端"加载更多"模式可直接用，不必自己算边界。

## 五、工作流

**① 进入收藏页**
点导航 → 路由守卫查 `gp_token`（无 → 跳登录并带 redirect）→ 进入组件 → `onMounted` → `fetchList()` → `GET /api/favorites?page=1&size=12` → 拦截器验 token/黑名单/角色 → `UserContext` 塞 userId → `selectMyPage`（JOIN 上架过滤 + 时间倒序）→ 批量查类型/当前价 → `toItem` 逐条算最低价与折扣 → `PageResult` → 渲染格子 + "共 N 款"。

**② 翻页**
点第 2 页 → `page=2` → 重新请求 → 后端 `Page(2,12)` → MP 改写 `LIMIT 12,12` → 返回新一页（总数不变，`hasMore` 由 `page*size<total` 算）。

**③ 取消收藏**
点"取消收藏" → 确认框（"再想想"可中止）→ `DELETE /api/favorites/9` → `delete where user_id=? and game_id=?` → 成功 → 若当页只剩这一条且 `page>1` 则 `page--` → 重拉列表（如果是第 1 页且删空 → 显示 `el-empty` 空态）。

**④ 空态**
`total=0` → 后端走 `PageResult.empty` → 前端 `list.length===0 && !loading` → 显示"还没有收藏任何游戏" + 去逛逛。

**⑤ 详情页状态与列表的联动**
详情页收藏/取消只改 `favorited` 布尔；**收藏页是独立请求实时拉的**，没有本地缓存，所以回到收藏页一定看到最新结果（不会出现"详情取消了但列表还留着"）。

## 六、涉及的知识点

1. **`total` 必须与 `list` 同源**：JOIN 过滤放进 SQL，MP 的 `count` 和 `select` 用的是同一条语句，天然一致；反之先分页再在 Java 里 `continue`，就会出现"共 8 款只显示 6 张"。
2. **MyBatis-Plus 分页拦截器**：`IPage` 入参 + `IPage` 返回 → 自动追加 `LIMIT` 并额外发 `count`；也因此 XML 里**不能有行尾 `--` 注释**（会吞掉自动追加的 LIMIT，第 13–18 行就是这条事故记录）。
3. **N+1 的批量化解法**：`Game` 一次 `in`、类型名一次 `in`、当前价一次 `IN`，3 次查询撑 12 条卡片；朴素写法是 12×3=36 次。
4. **价格口径复用而非重写**：收藏页调 `selectCurrentPrices`，与列表页/详情页同一段 SQL，从架构上消灭"两处价格不一样"。
5. **`hasQuote` 三态而不是 null 兜底**：后端显式给布尔，前端才敢直接 `hasQuote ? price : '暂无报价'`，不用 `v-if="item.minPriceCny != null"` 这种隐式判断（0 元和 null 会被混）。
6. **ThreadLocal 用户隔离**：`UserContext.requireUserId()` 让接口签名里没有 `userId`，越权改 id 这条路从协议层就不存在（AC-9.4）。
7. **唯一索引做并发兜底**：`uk_user_game(user_id, game_id)` 保证双击/双开标签页不会插两条，`DuplicateKeyException` 被吞成成功（`add` 第 88–92 行）。
8. **删除后的页码自愈**：第 61 行 `list.length===1 && page>1 → page--`，是最典型也最常被漏掉的体验细节。
9. **参数校验用注解 + 全局异常处理器**：`@Validated` + `@Min/@Max` 抛 `ConstraintViolationException` → `GlobalExceptionHandler` 第 56–62 行转成 `40000 参数不合法`，前端拿到的是统一错误体而不是 500。
10. **统一分页壳 `PageResult`**：列表页与收藏页共用（第 7 行注释就写了），`of/empty` 两个静态工厂 + `getTotalPages/isHasMore` 派生，前端不用自己算边界。
11. **`v-loading` 包在外层容器**：加载时不塌高度，避免网格闪烁。
12. **自适应网格 + `aspect-ratio`**：`auto-fill/minmax(190px,1fr)` 适配不同宽度；`3/4` 保证游戏竖版封面不拉伸。
13. **`v-if="total > size"` 隐藏无意义分页器**：只有一页时不显示页码组件。
14. **前端不做假分页缓存**：每次翻页/取消都重新请求，简单且绝不显示过期数据（代价是多几次请求，12 条/页完全可接受）。

## 七、现状与坑

1. **`favorite` 表现在 0 行**（`AUTO_INCREMENT=10`，测试数据被清过）：打开页面必然空态，AC-9 演示得先在详情页收藏几个。
2. **收藏时间是 ISO 带 `T` 原样输出**：`favoriteTime` 是 `LocalDateTime`，Jackson 默认 `2026-11-24T20:15:30`，前端第 127 行直接打印 → 界面会看到那个 `T`。修法二选一：后端 VO 加 `@JsonFormat(pattern="yyyy-MM-dd HH:mm")`，或前端 `item.favoriteTime?.replace('T',' ')`。
3. **没有排序/筛选/搜索**：列表固定"收藏时间倒序"，不能按价格排、不能筛"仅看打折"、不能搜名字。要加得在 `selectMyPage` 加参数或前端二次处理（不推荐）。
4. **没有"收藏数"角标**：`App.vue` 导航只有文字，不显示数量；要显示需新增 `GET /api/favorites/count` 或让前端在登录后拉一次 `size=1`。
5. **取消收藏是物理删除**：无软删、无审计，误点不可恢复（好在有确认框）。
6. **分页器不带总数/跳页**：`layout="prev, pager, next"`，页数很多时只能一页页点；可换 `total, sizes, prev, pager, next, jumper`。
7. **极端并发下 total 可能多 1**：SQL 已过滤 `status=1`，Java 第 184 行又 `continue`；若两次查询之间游戏被下架，`total` 会比实际渲染多一条（概率极低）。
8. **`list` 里 `Game` 查不到就跳过，但收藏记录还留着**：下架游戏会"永久占位"在 `favorite` 表里，用户看不见也删不掉（只能等游戏重新上架，或后台清理）。
9. **没有封面兜底图**：无 `coverUrl` 时显示灰底"暂无封面"，视觉上比默认占位图朴素；可换成统一 `placeholder.png`。
10. **移动端未适配**：`minmax(190px,1fr)` 在窄屏会变成 1 列，但没有专门的单列布局与字号调整。
