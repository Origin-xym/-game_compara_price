## 一、一句话链路

进详情页 → `GET /api/games/{id}` 一次拿到「游戏信息 + 每平台一张卡（现价/原价/折扣/风险/链接/史低/最低价标记）」→ 卡片用 `v-for` 渲染；走势另走 `GET /api/games/{id}/price-history?days=` → ECharts 一平台一条折线；史低来自**两条互不干扰的口径**（官方 `historical_low` 只展示，本站 `price_record` 历史最小），都在同一个 VO 里下发。

## 五、四条工作流

**① 进详情页**
`route.params.id` → `getGameDetail` → 后端查游戏（校验上架）→ 查当前价（统一口径）→ 无价分支 / 有价分支（排序 → 批量补平台/链接/风险/两种史低 → 装卡 → 追加占位卡）→ 返回 VO → `detail.value = data` → 卡片与头部渲染；`watch(route.params.id)` 支持“详情跳详情”。

**② 卡片渲染**
`v-for row in detail.platforms`，一张卡四列：平台（名称 + `lowest`/`stale`/`atLow` 标签）→ 价格（`hasPrice` 双分支）→ 风险 → 操作。`lowest` 由**后端排序后的第 0 行**决定，前端不重算；`atLow` 用“本站史低优先”。

**③ 走势渲染**
`PriceChart` 独立请求 `price-history` → `seriesList` 过滤 → `ensureChart` 保实例 → `setOption(..., true)`（`notMerge` 防残留）→ 每平台一条 `line`，`insufficient` 时只画点，`markLine` 画史低 → `resize` 监听窗口。

**④ 史低三处来源（不要混）**

- 卡片绿色「已到史低」：`atLow()` 前端判断，`本站史低 >= 现价`；
- 卡片下方橙色「史低 ¥11.00 本站记录」：`lowestEverCny`（`price_record` 历史最小）；
- 汇总区灰色「官方史低 ¥xx」：`historyLowCny`（`historical_low`，第三方授权源，AC-14.2 **只展示，不参与最低价**），走势里对应那条红虚线。

## 六、这套实现里的知识点

1. **口径单一化**：详情最低价、列表起价、走势、史低全都取决于同一条“当前价口径”（`is_current=1 AND status=1` + 平台 `enabled/api_ready/deleted`）。改一处必须同步四处，否则会出现“列表 ¥22 / 详情 ¥148”。
2. **VO 与 Entity 分离**：接口只吐 `GameDetailVO / PlatformPriceVO`，`Game` 实体的 `status/sort_weight` 不出网。
3. **无价 ≠ 0 元**：`hasQuote=false + minPriceCny=null`，前端显示“暂无报价”，避免被当成免费。
4. **占位卡的双开关**：`hasPrice=false` 表示“这个平台能买但没价”，与“没这个平台”（不在数组里）明确区分。
5. **排序保证唯一高亮**：`cnyAmount → recordedAt desc → platformId` 三级排序，价格相同也能稳定选出“唯一一张最低价卡”（AC-4.2 可复现）。
6. **汇率固化**：`originCny` 用 `price_record.rate`（入库时锁定），不用实时汇率，否则历史划线价会随汇率漂移。
7. **ECharts 生命周期**：`ensureChart`（DOM 变了重建）+ `dispose`（卸载/无数据时）+ `setOption(notMerge=true)`（防旧 series 残留）——这三件事缺一件就是白屏或串数据。
8. **`insufficient` 的两种呈现**：折线不画但**保留点**，比“整块空白”信息量大；同时给黄字说明，避免用户以为坏了。
9. **`markLine` 自检**：史低高于样本最低时直接不画 + `console.warn`，宁可少画不可画错（数据校准期的保护）。
10. **风险与可购性的不变式**：`purchasable = linkAvailable && riskLevel < 3`，卡片按钮文案与判断同源，不会出现“高风险还能点购买”。
11. **`watch` 路由参数**：SPA 里从 A 游戏跳到 B 游戏，组件被复用不会重新 `mounted`，必须 `watch(route.params.id)`。

## 七、当前已知限制

- `historical_low` 里 2 条还挂在已删的 1/3 号平台（被口径过滤），所以**“官方史低”全站为空**，只有“本站史低”在显示；
- `PriceTrendServiceImpl.loadHistoryLowMap()`（第 230–239 行）没按平台过滤，与详情页（第 415–419 行已按展示平台过滤）口径不完全一致，属于潜在不一致点；
- `/history-lows` 接口目前无人调用，可以删或留给“史低榜”；
- 走势数据积累依赖多次采集/录入，`CollectPriceWriter` 对“同价”不写历史点，所以同一个价反复采集不会增加点。
