## 一、一句话链路

“跳转官方商店”本质是**两条信息拼一条 URL**：平台的 `link_template`（如 `[https://store.steampowered.com/app/{externalId}?cc=cn](https://store.steampowered.com/app/{externalId}?cc=cn)`）+ 该游戏在该平台的 `external_id`（如 `289070`）；再由 `game_platform.store_url`（人工“覆盖链接”）优先顶替。生成发生在**服务端**，前端只拿 `shopUrl` 开新窗口。

## 二、用到的接口

| 接口 | 角色 | 说明 |
|---|---|---|
| `GET /api/games/{id}` | ✅ 前台唯一来源 | 每张卡片带 `shopUrl / linkAvailable / purchasable`，前端不拼串 |
| `GET /api/admin/games/{gameId}/links` | 后台维护 | 返回每平台的 `externalId / storeUrl / listed / effectiveUrl`（**`effectiveUrl` 就是服务端算出来的最终链接**，方便管理员验证） |
| `PUT /api/admin/games/{gameId}/links/{platformId}` | 后台维护 | 保存 `externalId / storeUrl / listed`（`GamePlatformLinkRequest`） |
| `POST/PUT /api/admin/platforms` | 后台维护 | 保存平台的 `linkTemplate`（含 `{externalId}` 强校验） |

| 平台 | shopUrl | purchasable |
|---|---|---|
| Steam | `[https://store.steampowered.com/app/289070?cc=cn](https://store.steampowered.com/app/289070?cc=cn)` | true |
| Epic Games | `[https://store.epicgames.com/zh-CN/p/](https://store.epicgames.com/zh-CN/p/)…` | true |

| 杉果 / steampy | 空（`external_id` 为 NULL → 生成失败） | false |

## 三、链接数据存在哪

| 位置 | 字段 | 语义 |
|---|---|---|
| `platform` | `link_template` | **平台级**模板，必须含 `{externalId}`（AC-7.2），如 `[https://store.steampowered.com/app/{externalId}?cc=cn](https://store.steampowered.com/app/{externalId}?cc=cn)` |
| `game_platform` | `external_id` | **游戏×平台级**外部 ID（Steam appid / Epic slug / 杉果 sku…） |
| `game_platform` | `store_url` | **覆盖链接**：填了就完全跳过模板（用于模板拼不对的平台） |
| `game_platform` | `listed` | 是否上架该平台（`0/1`），详情占位卡也认它 |
| `platform` | `enabled / api_ready / deleted` | 决定该平台是否进入前台口径（`deleted` 由 `@TableLogic` 逻辑删） |

## 五、工作流（配置 → 生成 → 点击）

1. **平台配置**（一次性）：后台新增平台，填 `linkTemplate`（必须含 `{externalId}`），保存时被第 159–162 行校验；
2. **游戏×平台绑定**（跟采集联动）：`SteamPriceSource` 采到 appid 后自动写 `game_platform.external_id`；其他平台在「游戏管理 → 链接」弹窗手填，或直接填「覆盖链接」跳模板；
3. **生成**：详情请求 → `linkMap` → `toPlatformRow` 按“覆盖优先、模板兜底”拼 `shopUrl`，同时算 `linkAvailable`、`purchasable`；
4. **点击**：`purchasable=true` → 「前往商店」→ `window.open(..., '_blank', 'noopener')`；
5. **兜底**：`externalId` 空 / 模板空 → `shopUrl=null` → `linkAvailable=false` → `purchasable=false` → 按钮不出现、显示原因（**不静默跳到错误页面**，AC-7.3）。

## 六、涉及的知识点

1. **单一数据源**：链接只在服务端算一次，前端永不 `concat`。这样“后台预览的生效链接”和“用户点到的链接”天然一致（`effectiveUrl` 与 `shopUrl` 用同一套优先级）。
2. **模板占位符 + 外部 ID 分离**：平台改版只改模板，不用批量改每款游戏；游戏换 ID 只改一行。
3. **null 合约**：`ShopLinkBuilder` 任一入参为空返回 `null`，而不是拼出 `.../app/?cc=cn` 这种半截链接——这是“宁可不可点，也不跳错页”的关键设计。
4. **覆盖链接的优先级**：`store_url` 一旦非空就完全跳过模板，适合“模板规律不适用”的平台（Epic 用 slug、杉果要 sku）。误操作风险是“把覆盖链接填成两段拼接”，后端 `blankToNull` 只能防空串，防不了错误内容。
5. **`linkAvailable` 与 `purchasable` 是两个概念**：前者“有没有链接”，后者“能不能买”（还要叠加 `riskLevel<3`）。UI 用 `purchasable` 一个布尔值决定按钮，保证提示与可购性不矛盾（AC-6.3）。
6. **`listed` 与 `enabled/api_ready` 是不同层级**：`enabled/api_ready` 是“平台整体是否上线/就绪”，`listed` 是“这个游戏在这个平台上架没有”。占位卡（`hasPrice=false`）用的是 `listed=1` + 平台 `enabled=1`。
7. **`window.open` 加 `noopener`**：防止目标页通过 `window.opener.location` 反向导航（钓鱼/劫持），这是外链的标配。
8. **审计**：`GamePlatformServiceImpl` 保存时把 `storeUrl` 前后值写进 `audit_log`，链接被谁改成什么可追溯（AC-7.3）。
9. **逻辑删除平台自动失效**：链接生成依赖 `platformMap`，而平台查询走 MyBatis-Plus → 已 `deleted=1` 的平台不在结果里，`shopUrl` 自然为 null，不会残留死链。
10. **URL 校验的边界**：`PlatformSaveRequest` 只校验“非空 + 含 `{externalId}` + 长度”，**没有校验 scheme**。管理员若把模板填成 `javascript:...` 会被原样下发（前台 `window.open` 会执行）。这是目前唯一的安全留白，加固方式是在 `ShopLinkBuilder.build` 里加 `StartsWith("http://")||("https://")` 白名单。

## 七、现状与坑（都是你已经踩过的）

1. **`external_id` 为空就看不了链接**：现在 `game_platform` 里 11/12/13 号平台（小黑盒/杉果/steampy）以及 10 号（EPIC）的 `external_id` **全是 NULL**，所以这三家的卡片只有“暂无链接”；
2. **覆盖链接被“追加”过一次**：之前 `game 9 / platform 9` 的 `store_url` 被粘成 `.../app/947510?cc=cn[https://store.steampowered.com/app/289070/](https://store.steampowered.com/app/289070/)...` 两段拼接，我们已把它置 NULL 让模板重新生成；
3. **各平台 ID 语义不同**：Steam 是 appid、Epic 是 slug（不是 appid）、杉果是站内 sku、小黑盒可直接复用 Steam appid（分享页 `?appid=`），填错就跳到别的游戏——这类错误系统**不会报错**，只能靠点一次验证；
4. **模板必须含 `{externalId}` 才能保存**：想“统一跳到官网首页”必须写成 `[https://xxx.com/home?kw={externalId}](https://xxx.com/home?kw={externalId})` 这种带占位的形态，否则第 159 行直接拦下。
