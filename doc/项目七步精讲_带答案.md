## 第 1 步：数据库骨架 + `common` 基座

### 1.1 这一节要解决什么

没有业务逻辑，只有两件事：**15 张表怎么组织**、**每个接口的返回长什么样**。这两样没搞清，后面 6 步都会“看得懂字、串不成线”。

### 1.2 15 张表分三圈

**第一圈：字典与主数据**

| 表 | 作用 | 关键约束 |
|---|---|---|
| `game_type` | 类型字典（3 条） | 只读，初始化 SQL 写入 |
| `game` | 游戏主数据（6 条） | `uk_name` 唯一 |
| `platform` | 平台（9 条在用 / 4 条已删） | `uk_code_region(code, region)` + `deleted` 逻辑删 |
| `game_platform` | 游戏 × 平台（35 条） | `external_id`（Steam appid / Epic slug）、`store_url`、`listed` |

**第二圈：价格链（全项目的心脏）**

```
platform
  └─ game_platform（这款游戏在这个平台的 id / 链接）
       └─ price_record          ← 每次采集/录入写一条
            ├─ is_current = 1   的那条 = 现在生效的价
            ├─ uk_current(game_id, platform_id, is_current)
            ├─ historical_low（官方史低，只展示不参与最低价）
            └─ exchange_rate_snapshot（汇率快照，折算 cny_amount）
```

`uk_current` 是地基：唯一索引是 `(game_id, platform_id, is_current)`，而 **MySQL 唯一索引允许多个 NULL**，于是：

- `is_current = 1` 只能有一条（当前价唯一，数据库级保证）
- `is_current = NULL` 可以有无数条（历史点、待确认记录都放这）

所以写入顺序只能是：**先把旧的那条改成 NULL，再插入新的 1**。反了直接撞索引。

**第三圈：用户与运维**

| 表 | 作用 | 约束 |
|---|---|---|
| `sys_user` | 用户（2 条） | `uk_username`，密码 BCrypt |
| `favorite` | 收藏 | `uk_user_game(user_id, game_id)`，无 `deleted` |
| `alert_rule` | 降价提醒 | `@TableLogic deleted`；`last_fired_price` 防重复通知 |
| `notification` | 站内通知 | 只读不删 |
| `region_risk` | 锁区风险 | `(platform_id, region)` |
| `admin_audit_log` | 后台留痕 | before/after JSON，只写不读 |
| `collect_task_log` | 采集批次 | status：0 运行中 / 1 成功 / 2 部分失败 / 3 失败 |
| `v_game_min_price` | 视图 | 辅助，不在主链路 |

**验证 SQL**

```sql
SELECT id,code,region,currency,enabled,api_ready,deleted FROM platform;
SELECT id,game_id,platform_id,cny_amount,is_current,status,recorded_at
FROM price_record ORDER BY id DESC LIMIT 8;
```

要读出三件事：① `platform` 里 `deleted=1` 的 4 条仍在库里但所有查询看不到；② 同 game+platform 只有一条 `is_current=1`；③ `status=2` 的待确认记录也是 `is_current=NULL`。

### 1.5 问答（带答案）

**Q1：`price_record` 的 `is_current` 为什么允许 NULL？**
> 唯一索引 `uk_current(game_id, platform_id, is_current)` 靠“多个 NULL 不冲突”的 MySQL 特性，让历史点和待确认记录可以无限多，同时保证当前价只有一条。

**Q2：平台被删了，历史价还在不在？前台能看到吗？**
> 在库里；前台看不到——所有查询都带 `platform.deleted = 0`。

**Q3：为什么代码里从不写 `setCreateTime`？**
> `BaseEntity` 用 `@TableField(fill=INSERT)` 声明，`MybatisMetaHandler` 在 insert 时自动填。

**Q4：`Result.errors` 什么时候出现？**
> 只有 `fail(errorCode, message, errors)` 这条路径（第 59–61 行），典型是后台表单的字段级错误。

**Q5：`BizException` 为什么重写 `fillInStackTrace`？**
> 业务异常是预期内的分支，不需要调用栈；省掉栈采集开销。

**Q6：`BlockAttackInnerInterceptor` 拦什么？**
> 没有 where 条件的全表 `update` / `delete`。

**Q7：`totalPages` 和 `hasMore` 是字段吗？**
> 不是字段，是 `PageResult` 的派生 getter（132 / 140 行），序列化后前端能直接用。

**Q8：`Result` 里的 `success` 从哪来？**
> `isSuccess()`（63 行）这个 getter 被 Jackson 当作属性序列化。

`GameServiceImpl.listGames`（88–150，核心段）：

```java
public PageResult<GameListItemVO> listGames(GameListQuery query) {
    // 1. 价格区间合法性
    if (query.getPriceMin() != null && query.getPriceMax() != null
            && query.getPriceMin().compareTo(query.getPriceMax()) > 0) {
        throw new BizException(ErrorCode.PARAM_INVALID, "价格区间起点不能大于终点");
    }
    // 2. 关键词规范化（trim → 去所有空格 → 小写 → 反查类型 id）
    prepareKeyword(query);

    // 3. 分页查询（SQL 侧完成搜索/筛选/计数）
    IPage<Game> page = new Page<>(query.getPage(), query.getSize());
    List<Game> games = gameMapper.selectAppPage(page, query);
    if (games.isEmpty()) {
        return PageResult.empty(query.getPage(), query.getSize());
    }

    List<Long> gameIds = games.stream().map(Game::getId).collect(Collectors.toList());

    // 4. 批量补类型名与当前价（避免 N+1）
    Map<Long, String> typeNameMap = loadTypeNames(games);
    Map<Long, List<CurrentPriceRow>> priceMap = loadCurrentPrices(gameIds);

    // 5. 组装
    LocalDateTime now = LocalDateTime.now();
    List<GameListItemVO> items = new ArrayList<>(games.size());
    for (Game g : games) {
        items.add(toItem(g, typeNameMap,
                priceMap.getOrDefault(g.getId(), Collections.emptyList()), now));
    }
    return PageResult.of(page.getTotal(), query.getPage(), query.getSize(), items);
}
```

```java
private void prepareKeyword(GameListQuery query) {
    String raw = query.getKeyword();
    if (raw == null || raw.isBlank()) {
        query.setKeyword(null); query.setKeywordNorm(null); query.setKeywordTypeIds(null);
        return;
    }
    String trimmed = raw.trim();
    query.setKeyword(trimmed);
    query.setKeywordNorm(trimmed.replaceAll("\\s+", "").toLowerCase(Locale.ROOT));
    query.setKeywordTypeIds(findTypeIdsByName(trimmed));   // AC-2.2 输入类型名命中该类型全部游戏
}
```

最低价 + 折扣（249–308 / 861–886）：

```java
private GameListItemVO toItem(Game g, Map<Long, String> typeNameMap,
                              List<CurrentPriceRow> prices, LocalDateTime now) {
    GameListItemVO vo = new GameListItemVO();
    vo.setId(g.getId()); vo.setName(g.getName()); vo.setNameEn(g.getNameEn());
    vo.setCoverUrl(g.getCoverUrl()); vo.setGameTypeId(g.getGameTypeId());
    vo.setGameTypeName(typeNameMap.get(g.getGameTypeId()));

    if (prices.isEmpty()) {                    // AC-1.3：无报价不返回 0
        vo.setHasQuote(false); vo.setMinPriceCny(null);
        vo.setPlatformCount(0); vo.setPlatforms(Collections.emptyList());
        vo.setHasDiscount(false); vo.setMaxDiscountRate(null); vo.setDiscountEndTime(null);
        return vo;
    }

    BigDecimal min = prices.stream().map(CurrentPriceRow::getCnyAmount)
            .filter(Objects::nonNull).min(Comparator.naturalOrder()).orElse(null);

    Map<Long, GameListItemVO.PlatformTag> tagMap = new LinkedHashMap<>();
    for (CurrentPriceRow row : prices) {
        tagMap.putIfAbsent(row.getPlatformId(),
                new GameListItemVO.PlatformTag(row.getPlatformId(),
                        row.getPlatformCode(), row.getPlatformName()));
    }

    vo.setHasQuote(true);
    vo.setMinPriceCny(min);
    vo.setPlatformCount(tagMap.size());
    vo.setPlatforms(new ArrayList<>(tagMap.values()));
    applyDiscount(vo, prices, now);
    return vo;
}

private void applyDiscount(GameListItemVO vo, List<CurrentPriceRow> prices, LocalDateTime now) {
    BigDecimal maxRate = null; LocalDateTime maxEnd = null;
    for (CurrentPriceRow row : prices) {
        BigDecimal dr = row.getDiscountRate();
        LocalDateTime end = row.getDiscountEndTime();
        boolean active = dr != null && dr.compareTo(BigDecimal.ZERO) > 0
                && (end == null || end.isAfter(now));
        if (active && (maxRate == null || dr.compareTo(maxRate) > 0)) {
            maxRate = dr; maxEnd = end;
        }
    }
    vo.setHasDiscount(maxRate != null);
    vo.setMaxDiscountRate(maxRate);
    vo.setDiscountEndTime(maxEnd);
}
```

### 2.6 工作流 12 步

1. `onMounted` 先 `fetchList()`，再并行拉平台/类型字典。
2. `buildParams()` 里空数组 → `undefined`，不污染 URL。
3. `GET /api/games`。
4. `@ModelAttribute` 逐字段 setter 绑定；`"9,10"` 由 Spring 转换器切成 `List<Long>`。
5. `@Valid` 跑 `@Min/@Max`；`size=51` → `40000` + `errors{size}`。
6. `priceMin > priceMax` → 直接报错，不查库。
7. 关键词 `"  赛博 朋克 "` → `"赛博朋克"`，并反查类型 id。
8. 分页插件自动补 count + LIMIT。
9. SQL 条件顺序：status → 关键词 → typeIds → platformIds(EXISTS) → 价格区间 → discountOnly(EXISTS) → ORDER BY。
10. 批量补类型名、当前价（12 张卡也只有 2 次额外查询）。
11. 组装 VO：无价 → `hasQuote=false`；有价 → min + tags + 最大折扣。
12. 前端解包 → 赋 `list/total` → 渲染。

### 2.7 问答（带答案）

**Q1：一个游戏在 5 个平台都有价，`selectAppPage` 返回它几行？**
> 一行。平台筛选用 `EXISTS` 子查询而不是 JOIN，避免行膨胀导致 `total` 和 LIMIT 错乱。

**Q2：`total` 谁算的？哪一行读出来？**
> 分页插件自动执行的 count；第 149 行 `page.getTotal()` 带进 `PageResult.of`。

**Q3：`size` 传 100 会怎样？**
> `@Max(50)` 拦下，返回 `40000` + `errors{size:"size 最大为 50"}`，不查库。

**Q4：卡片“暂无报价”时 `minPriceCny` 是 0 还是 null？为什么？**
> null。AC-1.3 明确要求无报价不返回 0，否则会显示“¥0 起”误导用户。

**Q5：平台标签的顺序由什么决定？**
> `selectCurrentPrices` 的 `ORDER BY p.cny_amount` + `LinkedHashMap.putIfAbsent` 的插入顺序 = 从便宜到贵。

**Q6：12 张卡片一共几条 SQL？**
> 3 条：`selectAppPage`（+1 条自动 count）、类型名 `selectList`、`selectCurrentPrices`。

**Q7：`hasQuote` 为 false 时会怎样排序？**
> 按 `sort_weight / create_time / id` 排，`minPriceCny` 不参与排序，所以无价游戏可能夹在中间、不会沉底。

**Q8：为什么 `@ModelAttribute` 而不是 `@RequestBody`？**
> GET 查询串用前者（逐字段 setter 绑定），POST JSON 才用后者。

### 2.8 坑

| 坑 | 说明 |
|---|---|
| `REPLACE(LOWER(...))` | 函数包裹让 `name` 索引失效；6 条无感，上千条会慢 |
| `size` 上限 50 vs 前端 12 | 后端允许到 50，前端固定 12 |
| `platformCount` 语义 | 是“有当前价的平台数”，不是 `game_platform.listed` 数 |
| `NOW()` vs `LocalDateTime.now()` | 同机一致，跨时区部署会偏差 |
| `SELECT g.*` | 把 summary 等无关字段也查出来再丢掉 |
| 无价游戏排序 | 见 Q7 |

```java
private PlatformPriceVO toPlatformRow(CurrentPriceRow row, Platform platform, GamePlatform link,
                                      RegionRisk risk, HistoricalLow low, boolean lowest, LocalDateTime now) {
    PlatformPriceVO vo = new PlatformPriceVO();
    vo.setPlatformId(row.getPlatformId());
    vo.setPlatformName(row.getPlatformName());
    vo.setCnyAmount(row.getCnyAmount());
    vo.setHasPrice(true);
    vo.setRate(row.getRate());
    vo.setRecordedAt(row.getRecordedAt());
    vo.setLowest(lowest);

    // 折扣过期后服务端不再返回折扣
    BigDecimal discountRate = row.getDiscountRate();
    LocalDateTime end = row.getDiscountEndTime();
    boolean discountActive = discountRate != null
            && discountRate.compareTo(BigDecimal.ZERO) > 0
            && (end == null || end.isAfter(now));
    vo.setDiscountActive(discountActive);
    vo.setDiscountRate(discountActive ? discountRate : null);
    vo.setDiscountEndTime(discountActive ? end : null);

    // 24 小时过期标记（app.price.stale-hours）
    vo.setStale(row.getRecordedAt() != null && row.getRecordedAt().isBefore(now.minusHours(staleHours)));

    // 跳转：覆盖链接优先，其次模板 + externalId
    String shopUrl = null;
    if (link != null && link.getStoreUrl() != null && !link.getStoreUrl().isBlank()) {
        shopUrl = link.getStoreUrl().trim();
    } else if (platform != null) {
        shopUrl = ShopLinkBuilder.build(platform.getLinkTemplate(),
                link == null ? null : link.getExternalId());
    }
    vo.setShopUrl(shopUrl);
    vo.setLinkAvailable(shopUrl != null);

    int level = (risk == null || risk.getRiskLevel() == null) ? 0 : risk.getRiskLevel();
    vo.setRiskLevel(level);
    vo.setRiskReason(level > 0 ? risk.getReason() : null);
    vo.setRiskSource(level > 0 ? risk.getSource() : null);

    // 史低只标注，绝不参与 minPrice
    if (low != null) {
        vo.setHistoryLowCny(low.getLowCny());
        vo.setHistoryLowAmount(low.getLowAmount());
        vo.setHistoryLowDate(low.getLowDate());
        vo.setHistoryLowSource(low.getSource());
    }

    vo.setPurchasable(shopUrl != null && level < 3);   // 高风险不给买
    return vo;
}
```

**Q3：走势里为什么有的平台只有圆点没有线？**

**Q4：`shopUrl` 为 null 时前端显示什么？由谁驱动？**

**Q5：`historyLowCny` 和 `lowestEverCny` 分别来自哪张表？**
> 前者 `historical_low`（官方，当前为空）；后者 `price_record` 历史最低（本站，有真实数据）。

**Q6：走势 SQL 为什么没有 `is_current = 1`？**
> 历史点写入后 `is_current` 变成 NULL；加上这个条件就只剩当前一个点，折线全没了。

**Q7：详情 5 条批量查询是哪 5 个？**
> `platformMap`、`linkMap`、`riskMap`、`lowMap`（官方史低）、`everLowMap`（本站史低）。

**Q8：为什么占位卡不过滤 `api_ready`？**
> “能不能显示”（`listed=1 && enabled=1`）与“能不能进最低价”（还要 `api_ready=1`）是两件事，必须分开。

## 第 4 步：登录注册 —— JWT + 拦截器 + ThreadLocal

### 4.1 链路

```
注册/登录（免登录）
  → @Valid 校验 DTO → 查用户 → BCrypt 校验 → 生成 JWT(sub=userId, username, role, jti, exp)
  → 返回 {token, expiresAt, user{...}} → 前端存 localStorage.gp_token

后续请求
  → 前端拦截器加 Authorization: Bearer <token>
  → AuthInterceptor.preHandle：验签 → 查黑名单 → 判角色 → UserContext.set(...)
  → Service 里 UserContext.requireUserId()
  → afterCompletion → UserContext.clear()

登出
  → 后端 jti 进 Redis 黑名单（TTL = token 剩余有效期）→ 前端删 localStorage
```

### 4.2 接口与实测

| 接口 | 鉴权 | 实测 |
|---|---|---|
| `POST /api/auth/register` | 否 | 返回 token，message=“注册成功” |
| `POST /api/auth/login` | 否 | 返回 token，message=“登录成功” |
| `GET /api/auth/me` | 是 | 无 token → `401 {"code":40100,"message":"请先登录","success":false}` |
| `POST /api/auth/logout` | 是 | 拉黑 jti |
| `/favorites/**`、`/alerts/**`、`/notifications/**` | 是 | 无 token → 401 40100 |
| `/admin/**` | 管理员 | 无 token → 401；登录但 role≠2 → `403 40301` |

```java
@Component
public class JwtUtil {
    private final SecretKey key;
    private final long expireMinutes;

    public JwtUtil(@Value("${app.jwt.secret}") String secret,
                   @Value("${app.jwt.expire-minutes:120}") long expireMinutes) {
        // HS256 要求密钥不少于 32 字节，否则 WeakKeyException
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expireMinutes = expireMinutes;
    }

    public TokenInfo generate(Long userId, String username, Integer role) {           // 50
        String jti = UUID.randomUUID().toString().replace("-", "");
        Date now = new Date();
        Date exp = new Date(now.getTime() + expireMinutes * 60_000L);
        String token = Jwts.builder()
                .id(jti)
                .subject(String.valueOf(userId))
                .claim("username", username)
                .claim("role", role)
                .issuedAt(now)
                .expiration(exp)
                .signWith(key)
                .compact();
        return new TokenInfo(token, jti, exp);
    }

    public Claims parse(String token) {                                              // 74
        return Jwts.parser().verifyWith(key).build()
                .parseSignedClaims(token).getPayload();
    }

    public boolean isExpiredException(Exception e) {                                 // 88
        return e instanceof ExpiredJwtException;
    }
}
```

```java
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    String header = request.getHeader("Authorization");
    if (header == null || header.isBlank()) throw new BizException(ErrorCode.UNAUTHORIZED);
    if (!header.startsWith("Bearer ")) throw new BizException(ErrorCode.TOKEN_INVALID);
    String token = header.substring(7).trim();

    Claims claims;
    try {
        claims = jwtUtil.parse(token);
    } catch (Exception e) {
        if (jwtUtil.isExpiredException(e)) throw new BizException(ErrorCode.TOKEN_EXPIRED);
        throw new BizException(ErrorCode.TOKEN_INVALID);
    }

    // 已登出的 token 直接拒绝
    String jti = claims.getId();
    if (jti != null && Boolean.TRUE.equals(redisTemplate.hasKey(BLACKLIST_PREFIX + jti))) {
        throw new BizException(ErrorCode.TOKEN_INVALID, "登录已失效，请重新登录");
    }

    Integer role = claims.get("role", Integer.class);
    if (requireAdmin && !Integer.valueOf(2).equals(role)) {
        throw new BizException(ErrorCode.ADMIN_ONLY);      // 后端拒绝；前端隐藏只是第二道
    }

    UserContext.set(new LoginUser(Long.valueOf(claims.getSubject()),
            claims.get("username", String.class), role));
    return true;
}

@Override
public void afterCompletion(HttpServletRequest req, HttpServletResponse resp, Object handler, Exception ex) {
    UserContext.clear();      // 线程复用，必须清理，否则会串号
}
```

```java
public LoginVO login(LoginRequest request) {                              // 131
    String username = request.getUsername().trim();
    SysUser user = userMapper.selectOne(new LambdaQueryWrapper<SysUser>()
            .eq(SysUser::getUsername, username));

    if (user == null) throw new BizException(ErrorCode.LOGIN_FAILED);   // 防用户名枚举
    if (!Integer.valueOf(1).equals(user.getStatus()))
        throw new BizException(ErrorCode.FORBIDDEN, "账号已被禁用，请联系管理员");
    if (user.getLockedUntil() != null && user.getLockedUntil().isAfter(LocalDateTime.now()))
        throw new BizException(ErrorCode.ACCOUNT_LOCKED,
                "登录失败次数过多，请于 " + user.getLockedUntil() + " 后重试");

    if (!passwordEncoder.matches(request.getPassword(), user.getPasswordHash())) {
        handleLoginFail(user);      // 内部必然抛异常
    }

    // 成功：清失败计数、清锁定、写最后登录时间
    userMapper.update(null, new LambdaUpdateWrapper<SysUser>()
            .eq(SysUser::getId, user.getId())
            .set(SysUser::getFailedCount, 0)
            .set(SysUser::getLockedUntil, null)
            .set(SysUser::getLastLoginTime, LocalDateTime.now()));
    return issueToken(user);
}

private void handleLoginFail(SysUser user) {                              // 187
    int failed = (user.getFailedCount() == null ? 0 : user.getFailedCount()) + 1;
    if (failed >= MAX_FAILED) {
        LocalDateTime until = LocalDateTime.now().plusMinutes(LOCK_MINUTES);
        userMapper.update(null, new LambdaUpdateWrapper<SysUser>()
                .eq(SysUser::getId, user.getId())
                .set(SysUser::getFailedCount, failed)
                .set(SysUser::getLockedUntil, until));
        throw new BizException(ErrorCode.ACCOUNT_LOCKED,
                "登录失败次数过多，账号已锁定 " + LOCK_MINUTES + " 分钟");
    }
    userMapper.update(null, new LambdaUpdateWrapper<SysUser>()
            .eq(SysUser::getId, user.getId()).set(SysUser::getFailedCount, failed));
    throw new BizException(ErrorCode.LOGIN_FAILED,
            "用户名或密码错误，还可尝试 " + (MAX_FAILED - failed) + " 次");
}

public void logout(String token) {                                        // 225
    if (token == null || token.isBlank()) return;
    try {
        Claims claims = jwtUtil.parse(token);
        String jti = claims.getId();
        Date exp = claims.getExpiration();
        long ttlMs = exp.getTime() - System.currentTimeMillis();
        if (jti != null && ttlMs > 0) {
            redisTemplate.opsForValue().set(BLACKLIST_PREFIX + jti, "1", Duration.ofMillis(ttlMs));
        }
    } catch (Exception e) {
        log.debug("登出时解析 token 失败: {}", e.getMessage());   // 已过期/非法，本身无法再用
    }
}
```

### 4.5 问答（带答案）

**Q1：token 里装了哪几样？**
> `jti`、`sub`（userId 字符串）、`username`、`role`、`iat`/`exp`。

**Q2：为什么 `afterCompletion` 必须 `clear()`？**
> Tomcat 线程池复用线程，ThreadLocal 不清会把上一个请求的用户带进下一个请求，造成串号/越权。

**Q3：登出后那个 token 还能用吗？TTL 为什么设“剩余时间”而不是固定 30 天？**
> 不能（jti 进黑名单）；TTL 设剩余时间，token 自然过期时黑名单条目也消失，不无限增长。

**Q4：普通用户（role=1）带 token 访问 `/admin/games`？**
> `403` + `{"code":40301,"message":"该操作仅管理员可用"}`。

**Q5：登录失败 5 次后第 6 次？**
> `40302` + “登录失败次数过多，账号已锁定 15 分钟”。

**Q6：`40100` 和 `40301` 前端分别做什么？**
> 40100 → 删 token + 跳登录（带 redirect）；40301 → 只弹提示，不跳页。

**Q7：为什么拦截器抛异常而不是 `return false` 写响应？**
> 抛 `BizException` 会走 `GlobalExceptionHandler`，401 的响应体和业务错误格式完全一致（都是 `Result`），不会出现 Tomcat 错误页。

**Q8：为什么“用户不存在”和“密码错误”同一个码？**
> 防止攻击者用返回文案枚举账号；代价是“不存在账号”不计失败次数（见坑表）。

**Q9：BCrypt 强度 10 意味着什么？**
> 每 `encode`/`matches` 约 60–80ms，能有效抬高暴力破解成本，同时不拖慢登录。

### 4.6 坑

| 坑 | 说明 |
|---|---|
| token 存 localStorage | XSS 可读；没有 httpOnly cookie 方案 |
| 无 refresh token | 120 分钟到点直接踢，表单会丢 |
| 改密码/禁用账号不失效旧 token | 拦截器不查库，只有 logout 才拉黑 |
| 黑名单只在 logout 写 | 管理员强制下线未实现 |
| `/auth/me` 每请求查库 | 频率低，可接受 |
| 不存在用户不计失败次数 | 只对真实用户累加 |
| POST 无 Content-Type → 500 | 415 未映射 |
| CORS 只允许 localhost | 上线要改，且不能 `*` 配 `allowCredentials(true)` |
| 密钥在配置文件明文 | 需换环境变量 |

```java
private boolean evaluate(AlertRule rule, ...) {
    List<CurrentPriceRow> prices = priceMap.getOrDefault(rule.getGameId(), Collections.emptyList());
    if (rule.getPlatformId() != null) {
        prices = prices.stream().filter(p -> rule.getPlatformId().equals(p.getPlatformId()))
                .collect(Collectors.toList());
    }
    if (prices.isEmpty()) return false;                       // AC-10.4 无价即不通知

    CurrentPriceRow cheapest = prices.stream()
            .min(Comparator.comparing(CurrentPriceRow::getCnyAmount)).orElse(null);
    if (cheapest == null || cheapest.getCnyAmount() == null) return false;
    BigDecimal current = cheapest.getCnyAmount().setScale(2, RoundingMode.HALF_UP);

    boolean matched; String conditionDesc;
    switch (rule.getType()) {
        case 1 -> { matched = rule.getTargetPrice() != null
                && current.compareTo(rule.getTargetPrice()) <= 0;
                conditionDesc = "达到目标价 ¥" + rule.getTargetPrice(); }
        case 2 -> { BigDecimal low = resolveLow(rule, lowMap);
                matched = low != null && current.compareTo(low) <= 0;
                conditionDesc = "跌至官方史低 ¥" + low; }

                && current.compareTo(rule.getBaselinePrice()) < 0;
                conditionDesc = "低于设置时价格 ¥" + rule.getBaselinePrice(); }
    }
    if (!matched) return false;

    // 幂等核心：同价位不重复通知；价格没有比上次更低也不再通知
    if (rule.getLastFiredPrice() != null && current.compareTo(rule.getLastFiredPrice()) >= 0) {
        return false;

            .eq(AlertRule::getId, rule.getId())
            .set(AlertRule::getLastFiredPrice, current)
            .set(AlertRule::getLastFiredTime, LocalDateTime.now()));
```

### 5.6 案例：库里那条提醒为什么永远不响

### 5.7 问答（带答案）

**Q1：连点 5 次收藏，表里几条？返回几次成功？**
> 1 条；5 次都成功（`selectCount` 幂等 + `uk_user_game` 兜底 + 捕获 `DuplicateKeyException`）。

**Q2：为什么 total 必须在 SQL 里过滤下架游戏？**
> 否则“共 3 款”但只显示 2 张卡，分页也会错位；`total` 与 `list` 必须同源。

**Q3：`last_fired_price` 能挡住哪三种重复通知？**
> 同价位重复触发；涨价后回到原价再触发；在阈值附近来回抖动。

**Q4：目标价填 300（现价 298）会怎样？**
> `40003`：“目标价需低于当前最低价 ¥298.00”，规则建不出来。

**Q5：规则指向已删平台，任务怎么做？**
> `prices` 过滤后为空 → 直接 `return false`，静默不触发也不打日志。

**Q6：`baseline_price` 和 `last_fired_price` 分别是什么？**
> 前者是“设置提醒时的价”（type=3 判“低于它”）；后者是“上次发通知时的价”（防重复）。

**Q7：`requireOwn` 为什么统一报 404？**
> 防止探测“规则存在但不属于你”；不存在与无权限返回一致。

**Q8：判定任务每轮几条 SQL？**
> 5 条：规则列表、游戏、当前价、官方史低、平台名各 1 条（全部批量，与规则条数无关）。

### 5.8 坑

| 坑 | 说明 |
|---|---|
| 通知与 `last_fired` 更新不同事务 | 通知写成功、更新失败 → 下一轮重复通知 |
| 每轮最多 500 条 | 超出的规则永远判不到（无分页游标） |
| 调度器默认单线程 | 判一环慢会推迟 04:00 采集（`spring.task.scheduling.pool.size` 未配） |
| type=2 依赖 `historical_low` | 该表全空 → “跌至史低”提醒一个都建不了 |
| 暂停的规则不算重复 | 已暂停时能再建一条一模一样的，恢复后两条并存 |
| 通知不可删 | 只有已读/全部已读 |
| 待确认队列无通知 | 采集进 `status=2` 时不会提醒 |
| 收藏页无提醒入口 | 必须进详情页设提醒 |
| `listMine` 不分页 | 规则多了一次全返回 |

```java
            else if (!en.isEmpty() && name.equals(en)) score = 1000;
            else if (!en.isEmpty() && name.startsWith(en)) score = 800;
            else if (!cn.isEmpty() && name.startsWith(cn)) score = 800;

            || n.contains("phantom liberty") || n.contains("shadow of the erdtree")
            || n.contains("friend's pass") || n.contains("nightreign");
```

### 6.6 写入（`CollectPriceWriter.write` 37–158，节选）

```java
@Transactional(rollbackFor = Exception.class)     // 归档+插入必须原子
public int write(CollectItem item, Platform platform, String batchNo,
                 int sourceType, BigDecimal threshold) {

    // 1. 五道脏数据拦截
    if (item.getOriginalAmount() == null || item.getOriginalAmount().compareTo(BigDecimal.ZERO) <= 0)
        throw new IllegalArgumentException("金额必须大于 0");
    if (item.getCurrency() == null || !item.getCurrency().equalsIgnoreCase(platform.getCurrency()))
        throw new IllegalArgumentException("币种不符，应为 " + platform.getCurrency());
    BigDecimal amount = item.getOriginalAmount().setScale(2, RoundingMode.HALF_UP);

    BigDecimal originalPrice = item.getOriginalPrice();
    BigDecimal discountRate = item.getDiscountRate() == null ? BigDecimal.ZERO : item.getDiscountRate();
    if (discountRate.compareTo(BigDecimal.ZERO) > 0) {
        if (originalPrice == null) throw new IllegalArgumentException("有折扣率但缺原价");
        originalPrice = originalPrice.setScale(2, RoundingMode.HALF_UP);
        if (originalPrice.compareTo(amount) < 0) throw new IllegalArgumentException("原价低于现价");
        if (item.getDiscountEndTime() != null
                && item.getDiscountEndTime().isBefore(LocalDateTime.now()))
            throw new IllegalArgumentException("折扣截止时间早于当前时间");
    } else {
        originalPrice = amount;
    }

    // 2. 汇率固化
    RateInfo rateInfo = exchangeRateService.getRateToCny(platform.getCurrency());
    BigDecimal cny = amount.multiply(rateInfo.getRate()).setScale(2, RoundingMode.HALF_UP);

    // 3. 读当前价
    PriceRecord current = priceRecordMapper.selectOne(new LambdaQueryWrapper<PriceRecord>()
            .eq(PriceRecord::getGameId, item.getGameId())
            .eq(PriceRecord::getPlatformId, item.getPlatformId())
            .eq(PriceRecord::getIsCurrent, 1)
            .last("LIMIT 1"));

    // 4. B 方案：同日去重、跨天必写
    if (current != null && current.getCnyAmount() != null
            && current.getCnyAmount().compareTo(cny) == 0) {
        LocalDateTime todayStart = LocalDate.now().atStartOfDay();
        long todayCount = priceRecordMapper.selectCount(new LambdaQueryWrapper<PriceRecord>()
                .eq(PriceRecord::getGameId, item.getGameId())
                .eq(PriceRecord::getPlatformId, item.getPlatformId())
                .eq(PriceRecord::getStatus, 1)
                .ge(PriceRecord::getRecordedAt, todayStart));
        if (todayCount > 0) return 0;      // 今天已有生效点 → 跳过
        log.info("价格未变但今日无采样点，补一条历史点 ...");
    }

    PriceRecord record = new PriceRecord();
    record.setGameId(item.getGameId());
    record.setPlatformId(item.getPlatformId());
    record.setCurrency(platform.getCurrency());
    record.setOriginalAmount(amount);
    record.setOriginalPrice(originalPrice);
    record.setDiscountRate(discountRate);
    record.setDiscountEndTime(discountRate.compareTo(BigDecimal.ZERO) > 0
            ? item.getDiscountEndTime() : null);
    record.setRate(rateInfo.getRate());
    record.setRateTime(rateInfo.getFetchedAt());
    record.setCnyAmount(cny);
    record.setSourceType(sourceType);
    record.setSourceRef(batchNo);
    record.setOperator("collect:" + batchNo);
    record.setRecordedAt(LocalDateTime.now());

    // 5. 剧烈波动 → 待确认，不覆盖线上
    boolean abnormal = current != null && current.getCnyAmount() != null
            && current.getCnyAmount().compareTo(BigDecimal.ZERO) > 0
            && cny.subtract(current.getCnyAmount()).abs()
                 .divide(current.getCnyAmount(), 4, RoundingMode.HALF_UP)
                 .compareTo(threshold) > 0;
    if (abnormal) {
        long samePending = priceRecordMapper.selectCount(new LambdaQueryWrapper<PriceRecord>()
                .eq(PriceRecord::getGameId, item.getGameId())
                .eq(PriceRecord::getPlatformId, item.getPlatformId())
                .eq(PriceRecord::getStatus, 2)
                .isNull(PriceRecord::getIsCurrent)
                .eq(PriceRecord::getCnyAmount, cny));
        if (samePending > 0) return 0;          // 同价待确认已存在，不重复入队
        record.setIsCurrent(null); record.setStatus(2);
        priceRecordMapper.insert(record);
        return 2;
    }

    // 6. 唯一生效：先归档，后插入（顺序不可颠倒）
    priceRecordMapper.update(null, new LambdaUpdateWrapper<PriceRecord>()
            .eq(PriceRecord::getGameId, item.getGameId())
            .eq(PriceRecord::getPlatformId, item.getPlatformId())
            .eq(PriceRecord::getIsCurrent, 1)
            .set(PriceRecord::getIsCurrent, null));

    record.setIsCurrent(1); record.setStatus(1);
    priceRecordMapper.insert(record);
    return 1;
}
```

### 6.8 问答（带答案）

**Q1：`total=6` 但 `success=0` 是怎么回事？**
> 同价 + 当天已有 `status=1` 采样点 → 每条都 `return 0`（skip），`fail=0` 所以 status 判成功。

**Q2：小黑盒采集走到哪一步失败？日志里能看到什么？**
> `SourceRegistry.find` 返回 null → 日志 status=3 + “暂无可用采集器”，并抛 `40903`。

**Q3：阈值 0.5 的含义？新价 30、旧价 298 会怎样？**
> 偏离超过 50% 视为异常；30 vs 298 约 90% → 进 `status=2` 待确认，不覆盖线上。

**Q4：为什么必须“先归档再插入”？**
> `uk_current` 只允许一条 `is_current=1`；反序会撞索引，先归档才不会冲突。

**Q5：新增“杉果”采集器要改几个文件？**
> 1 个：新增 `implements PriceSource` 的 `@Component`，声明 `platformCodes()={"SHANGUO"}`；注册表和采集服务都不动。

**Q6：Mock 在 NORMAL 场景会抢真实源的活吗？**
> 不会。`@Order(100)` 排在真实源之后，`find` 取第一个命中的。

**Q7：`write()` 的四种返回值分别代表什么？**
> 1 = 写入当前价；0 = 跳过（同价且当天有点 / 同价待确认已存在）；2 = 进待确认；抛异常 = 该条失败。

**Q8：Steam 的 `final`/`initial` 为什么要 `BigDecimal.valueOf(v, 2)`？**
> Steam 返回的是“分”，`scale=2` 直接转成“元”，避免手写 `/100` 引入精度问题。

**Q9：汇率为啥不影响历史价？**
> `cny_amount / rate / rate_time` 入库即固化，后续汇率变化不回溯。

### 6.9 坑

| 坑 | 说明 |
|---|---|
| `success=0` 也显示“成功” | 全跳过时 `status=1`，前端看不出“其实没更新” |
| 无并发锁 | 连点/定时与手动撞车可能撞唯一索引，其中一条 fail |
| `sleep(200/300ms)` 串行 | 6 条约 1.2s；上百款要几分钟且占调度线程 |
| 采集会写 `game_platform` | Steam 补链是“采集的副作用”，排查数据异常要想到 |
| 补链可能绑错 | 有评分 + DLC 降权，但仍可能把重制版绑成原版；绑上后不再重搜 |
| Epic 无补链 | slug 只能人工填 → 现在永远 `total=0` |
| 汇率不自动刷新 | 只用 seed 快照，缺币种整条 fail |
| 待确认无通知 | 入队后没人知道 |
| `run-all` 顺序执行 | 一个平台超时会拖慢后面 |
| 定时任务单线程 | 与提醒判定共用默认调度器，互相挤 |

### 7.7 问答（带答案）

**Q1：删了 `STEAM/CN` 再新增同名，会发生什么？为什么不能直接 insert？**
> 走“复活”分支：查已删行 → 设回旧 id → `restore(deleted=0 + 刷新字段)`。直接 insert 会撞 `uk_code_region` 1062，因为逻辑删的行仍占索引位置。

**Q2：为什么 `restore` 必须手写 SQL？**
> MP 的 `updateById` 会自动加 `deleted=0` 条件，永远改不到已删行；只有手写 SQL 能改 `deleted`。

**Q3：币种从 USD 改 CNY，历史价会变吗？**
> 不会。`cny_amount / rate / rate_time` 入库已固化，改平台只影响此后新写入的价格。

**Q4：新增游戏名称重复，前端怎么把红字显示在“名称”输入框下？**
> 后端 `BizException(DUPLICATE_GAME, "该游戏已存在", Map.of("name", ...))` → 全局处理器把 `errors` 放进 `Result` → 前端 `if (e.errors) fieldErrors.value = e.errors`。

**Q5：`dataSourceType=3` 为什么强制 `api_ready=0`？**
> 纯手动平台没有数据源，永远不该进入“有当前价”的口径；强制置 0 从根上杜绝配置错误。

**Q6：编辑游戏名称会动到收藏和提醒吗？**
> 不会。只 `update game` 表，价格历史/收藏/提醒都不动。

**Q7：`ensureUnique` 存在的意义？**
> 把 MySQL 的 1062 变成人话（“已存在同编码同区域平台：STEAM/CN”），避免前端看到原始 SQL 报错。

**Q8：审计失败会怎样？**
> 只打 error 日志，不影响主流程（留痕是旁路）。
