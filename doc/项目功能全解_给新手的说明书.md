## 0. 这个项目到底是什么

**一句话**：把同一款游戏在 STEAM、EPIC、小黑盒、杉果、steampy 上的价格汇总到一张卡片里，用人民币显示最低价，配上历史走势、史低价、锁区风险，并支持收藏和降价提醒。

**它解决的真实问题**：同一款《赛博朋克2077》，Steam 国区 298 元、Epic 可能 182 元、小黑盒可能 22 元（活动价）。用户不想开 5 个网站比价，也不想天天手动查价格。

**三类角色，看到的东西完全不同**：

| 角色 | 能做什么 | 怎么进 |
|---|---|---|
| 游客 | 浏览列表、搜索、看详情/走势/史低、点"去商店" | 直接打开首页 |
| 登录用户 | 上述全部 + 收藏、设降价提醒、收站内通知 | `/login` 注册/登录 |
| 管理员 | 上述全部 + 4 个后台页（游戏/平台/价格审核与采集/锁区） | 账号 `role=2` |

**前台 5 个页面 + 后台 4 个页面**：

```
前台：/games（列表）  /games/:id（详情）  /favorites（我的收藏）  /alerts（我的提醒）  /notifications（通知）
后台：/admin/games（游戏管理）  /admin/platforms（平台信息）  /admin/prices（价格审核+采集）  /admin/risks（锁区维护）
公共：/login（登录/注册二合一）
```

## 1. 先看懂三层架构（看懂这个，后面全是细节）

```
你的浏览器（Vue 页面）
   │  ① 点按钮 → 调用 api/xxx.js
   │  ② axios 拦截器：自动加 Authorization: Bearer <token>
   ▼
HTTP 请求（JSON）  →  http://localhost:8081/api/...
   │
   ▼
Spring Boot 后端
   ├─ 拦截器 AuthInterceptor：验 token、验角色、把"当前用户"塞进 ThreadLocal
   ├─ Controller：只负责"收参数、返回结果"（不写业务）
   ├─ Service：业务规则都在这里（校验、算价、写库、审计）
   ├─ Mapper（+ XML）：真正拼 SQL 的地方（MyBatis-Plus）
   ▼
MySQL（game_compara_price）  +  Redis（token 黑名单、缓存）
```

### 1.1 每一层在项目里的位置

| 层 | 后端目录 | 前端对应 |
|---|---|---|
| 接口层 | `*/controller/*.java` | `src/api/*.js`（8 个文件） |
| 业务层 | `*/service/impl/*.java` | `src/views/*.vue`（10 个页面） |
| 数据层 | `*/mapper/*.java` + `resources/mapper/*.xml` | `src/stores/*.js`（本地状态） |
| 数据结构 | `*/entity`（表）、`*/dto`（入参）、`*/vo`（出参） | — |
| 基础设施 | `common`（Result/异常/分页）、`config`、`security` | `utils/request.js`、`router/index.js` |

### 1.2 必须认识的名词（不会这些，代码像天书）

| 名词 | 通俗解释 | 在本项目里的例子 |
|---|---|---|
| **Entity（实体）** | 一张数据库表的 Java 镜像，字段一一对应 | `Game`、`PriceRecord`、`Platform` |
| **DTO（入参对象）** | 前端传上来的数据长什么样，带校验注解 | `GameSaveRequest`（名称必填、年份 1970–2100） |
| **VO（出参对象）** | 返回给前端的数据长什么样（常是实体加工后的结果） | `GameListItemVO`（多了"最低价/平台标签"） |
| **Mapper** | 数据库操作接口，MyBatis-Plus 自动实现大部分 | `GameMapper.selectPage(...)` |
| **Wrapper（条件构造器）** | 用 Java 代码"拼 where 条件"，不用手写 SQL | `new LambdaQueryWrapper<Game>().eq(Game::getStatus, 1)` |
| **Result** | 统一返回壳 `{code, message, data}`，`code=0` 表示成功 | 所有接口的返回值 |
| **PageResult** | 统一分页壳 `{total, page, size, list, totalPages, hasMore}` | 列表/收藏/通知 |
| **ThreadLocal** | 一条请求一个"随身口袋"，拦截器放用户，Service 取 | `UserContext` |
| **拦截器** | 请求进 Controller 之前的一道闸门 | `AuthInterceptor`（401/403 就是它拦的） |
| **事务 `@Transactional`** | 一组写操作要么全成功、要么全回滚 | "归档旧价+插入新价"必须原子 |
| **唯一索引** | 数据库层面的"不许重复"硬约束 | `favorite(user_id, game_id)`、`platform(code, region)` |
| **逻辑删除 `@TableLogic`** | 不真删，只把 `deleted` 置 1，查询自动过滤 | 平台删除、提醒删除 |
| **定时任务 `@Scheduled`** | 到点自动跑的方法 | 每天 04:00 采集、每分钟查提醒 |

## 4. 五条贯穿全局的规则（不懂这五条，任何功能都会看歪）

### 规则 1：价格的"统一口径"

全站只有一种"有效价格"的定义，写在 SQL 里，所有页面复用：

```
price_record：is_current = 1  AND  status = 1
platform：   enabled = 1  AND  api_ready = 1  AND  deleted = 0
```

- `is_current=1`：这条是"现在生效的价"；同一游戏同一平台永远只有一条（唯一索引保证）。
- `status`：`1 生效 / 2 待确认 / 3 已驳回`。
- 平台三个开关任一不满足 → 该平台的价格**整体退出**全站（不显示、不参与最低价、不画走势、不采集）。

出现位置：`GameMapper.xml` 的 `minPriceExpr`、`PriceRecordMapper.xml` 的 `selectCurrentPrices` / `selectHistory`、列表 SQL。

### 规则 2：人民币价格"入库即固化"

每条价格入库时都会写三个字段：`rate`（汇率）、`rate_time`（汇率时间）、`cny_amount`（折算后人民币）。
**之后汇率再变，也不回头改历史价**。否则"历史最低价"会天天变，比价就失去意义。

### 规则 3：权限三层 + "当前用户"靠 ThreadLocal

| 层 | 范围 | 失败返回 |
|---|---|---|
| 公开 | `/games/**`、`/platforms`、`/game-types`、注册/登录 | — |
| 需登录 | `/favorites/**`、`/alerts/**`、`/notifications/**`、`/auth/me`、`/auth/logout` | `40100/40102/40103` |
| 仅管理员 | `/admin/**`（`requireAdmin=true`，还要求 `role=2`） | `40301` |

登录后，拦截器把 `LoginUser(id, username, role)` 放进 `UserContext`（ThreadLocal），Service 里一句 `UserContext.requireUserId()` 就拿到当前用户——**接口参数里没有 userId，所以改不了别人的数据**。请求结束必须 `clear()`，否则线程复用会串号。

### 规则 4：返回体与错误码统一

所有接口返回 `Result{code, message, data}`，`code=0` 成功。错误码分段：

```
400xx 参数  401xx 认证  403xx 权限  404xx 不存在  409xx 冲突  5xxxx 系统
```

前端 `utils/request.js` 统一处理：`code===0` 才把 `data` 返回给页面；`401xx` 清 token 并跳登录；其余弹 `ElMessage.error`；字段级错误放进 `e.errors`（后台表单用来显示"某字段红字"）。

### 规则 5：能恢复的删除用"逻辑删除"

- 平台：`deleted` + `@TableLogic`，删了还能用"同编码+区域"重建恢复（`restore`）。
- 提醒：软删，历史通知保留。
- 收藏：物理删（简单，无审计）。
- 游戏：不删，只有"上架/下架"（`status`）。

> 判断标准：**删了会不会影响历史数据/关联数据**。会影响就用逻辑删。

## 5. 功能逐个讲（统一模板）

每个功能都按这 6 个问题看：**解决什么 → 从哪里进 → 后端怎么走 → 前端怎么走 → 数据怎么变 → 看哪些文件**。

### 5.1 注册 / 登录

- **解决什么**：区分"游客"和"有身份的用户"，让收藏/提醒能归属到人。
- **入口**：`/login`，一个页面双模式（登录/注册切换）。
- **后端**：`POST /auth/register`（用户名查重 → BCrypt 加密 → 插库 `role=1` → **直接签发 token**，注册即登录）；`POST /auth/login`（查用户 → 状态/锁定检查 → 密码 `matches` → 失败 5 次锁 15 分钟 → 成功清零计数 → 签发 JWT）。
- **前端**：`LoginView.vue` 调 `stores/user.js` 的 `login/register`，token 存 `localStorage.gp_token`，然后跳回 `redirect` 或 `/games`。
- **数据**：`sys_user` 新增/更新（`failed_count`、`locked_until`、`last_login_time`）；Redis 无写入（登出才写）。
- **文件**：`user/controller/AuthController`、`user/service/impl/AuthServiceImpl`、`security/JwtUtil`、`config/WebMvcConfig`（密码器）、`stores/user.js`、`utils/request.js`。
- **坑**：token 只在 localStorage，XSS 可窃取；120 分钟到期必须重登（无 refresh token）。

### 5.2 游戏列表（首页）

- **解决什么**：一屏看到所有游戏及其"当前全站最低价"。
- **入口**：`/games`。
- **后端**：`GET /games` → `GameServiceImpl.listGames` → 一段带 `minPriceExpr` 的大 SQL（`GameMapper.xml` 33–125 行）：一次查出游戏 + 最低价 + 平台标签 + 折扣，**不做 N 次单查**。
- **前端**：`GameList.vue` + `GameCard.vue`；价格显示"¥xx / 暂无报价"，折扣显示 `-xx%`。
- **数据**：只读。
- **文件**：`game/controller/GameController`、`game/service/impl/GameServiceImpl`（88–280 行）、`resources/mapper/GameMapper.xml`、`views/list/GameList.vue`、`components/GameCard.vue`。
- **坑**：`hasQuote=false` 时前端必须显示"暂无报价"，不能显示 `¥0.00`。

### 5.3 名称搜索 + 类型/平台/价格/折扣筛选

- **解决什么**：游戏多了以后快速找到目标。
- **入口**：首页搜索框 + 筛选条（`SearchBox.vue` / `FilterBar.vue` / `ConditionTags.vue`）。
- **后端**：同一个 `GET /games`，参数 `keyword / typeIds / platformIds / priceMin / priceMax / discountOnly`。
  - 关键词做了"去空格 + 小写"归一（`prepareKeyword` 130–150 行），SQL 里用 `REPLACE(LOWER(name),' ','') LIKE` 匹配，所以"赛博 朋克"也能搜到《赛博朋克2077》。
  - 关键词还会去匹配类型名（搜"角色扮演"能出该类型全部游戏）。
- **前端**：搜索框 300ms 防抖；条件用 tag 展示，可单个删除。
- **数据**：只读。
- **文件**：`GameListQuery`、`GameServiceImpl.prepareKeyword/findTypeIdsByName`、`GameMapper.xml`、`SearchBox.vue`、`FilterBar.vue`。
- **坑**：关键词用了 `%kw%`，数据量大时走不了索引（当前 6 款游戏无感）。

### 5.4 游戏详情（多平台价格卡片）

- **解决什么**：一个游戏在几个平台各多少钱、谁最便宜、值不值得买。
- **入口**：点卡片 → `/games/:id`。
- **后端**：`GET /games/{id}` → `getGameDetail`（282–414 行）：查游戏 → 查当前价 → 按 `cnyAmount, recordedAt desc, platformId` 排序保证"最低"唯一 → 组装每平台一行（`toPlatformRow`：折扣、是否过期 `stale`、商店链接、是否可购买）→ 没有价格的平台**出占位卡**（`buildPlaceholderRows`）。
- **前端**：`GameDetail.vue` 顶部价格区 + `PriceChart` + 平台价签列表 + "收藏/提醒/去商店"按钮。
- **数据**：只读（收藏状态另调 `/favorites/{id}/exists`）。
- **文件**：`GameServiceImpl.getGameDetail`（282–414）、`toPlatformRow`（452–521）、`buildPlaceholderRows`（523–604）、`PlatformPriceVO`、`views/detail/GameDetail.vue`。
- **坑**：占位卡只认"平台启用 + 该游戏对该平台上架"，所以新增平台后要维护 `game_platform` 的 `listed`。

### 5.5 价格走势（一平台一条折线）

- **解决什么**：看出"现在是贵还是便宜"，以及"哪个平台在降"。
- **入口**：详情页下方图表，可切 30/90/365 天。
- **后端**：`GET /games/{id}/price-history?days=90` → `PriceTrendServiceImpl.getHistory`：按平台分组，每组按时间排序取点；天数限制 7–365，非法直接报错。
- **前端**：`PriceChart.vue` 用 ECharts：每个平台一条 `line`；只有一个点的平台 `lineStyle.width=0` 只画圆点；史低用虚线 `markLine`；`notMerge=true` 防切换游戏残留旧线。
- **数据**：只读 `price_record` 历史点（`is_current` 为 1 或 NULL 都算历史）。
- **文件**：`price/service/impl/PriceTrendServiceImpl`（53–140）、`PriceRecordMapper.xml` 的 `selectHistory`（99–120）、`components/PriceChart.vue`。
- **坑**：**只有价格变化（或跨天首次采集）才会产生新点**。同一天反复点采集不会加点——这是为了避免走势被 `¥22.00 × 10 次` 刷成噪声。

### 5.6 史低（两个口径，别搞混）

| 口径 | 字段 | 来源 | 用途 |
|---|---|---|---|
| 本站史低 | `lowestEverCny / lowestEverAt` | 本站 `price_record` 历史最小值（已赋值） | 详情卡"史低 ¥xx 本站记录" |
| 官方史低 | `historyLowCny` | `historical_low` 表（第三方授权） | 只做展示/虚线标注 |

- **数据现状**：`historical_low` 两条都挂在**已删除**的 platform 1/3 上，被 `in(platformIds)` 过滤 → 目前**全站官方史低为空**。这是数据问题，不是代码问题。
- **文件**：`GameServiceImpl.everLowMap`（359–392）、`PriceTrendServiceImpl.listHistoryLows`、`AdminHistoryLowController`（唯一一个 upsert 接口）。

### 5.7 折扣标记 + 锁区风险

- **后端链路**：
  1. `CollectServiceImpl.run` 校验平台（非纯手动/已启用/已就绪）→ 生成批次号 → **先落一条"运行中"日志**。

## 7. 推荐阅读顺序（7 步，每步 1–2 小时）

| 步 | 读什么 | 要搞懂什么 | 怎么验证 |
|---|---|---|---|
| 1 | 建表 SQL + `common/*` + `BaseEntity` | 15 张表的关系；`Result/PageResult` 长什么样 | 用 `mysql` 看 `price_record` 的 `uk_current` |
| 2 | `GameController` → `GameServiceImpl.listGames` → `GameMapper.xml` | 列表的"一条 SQL 出全部信息"是怎么写的；`minPriceExpr` 口径 | 浏览器看 `/games` 返回 JSON |
| 3 | `getGameDetail`（282–414）+ `PriceChart.vue` | VO 是怎么组装的；占位卡；走势按平台分组 | 打开详情，切 30/90/365 天 |
| 4 | `AuthController` / `AuthInterceptor` / `JwtUtil` / `UserContext` | token 怎么发、怎么验、当前用户怎么传 | 不带 token 调 `/favorites` 看 40100 |
| 5 | `FavoriteServiceImpl` + `AlertServiceImpl` + `AlertCheckJob` | ThreadLocal 复用；幂等；定时任务去重（`last_fired_price`） | 设一个提醒，等 1 分钟看通知 |
| 6 | `CollectServiceImpl` + `CollectPriceWriter` + `PriceSource` | 策略模式；每条一个事务；"归档后插入"；同价跳过；波动入队 | 后台点采集，看批次日志与 `price_record` |
| 7 | `PlatformAdminServiceImpl` + `GameServiceImpl.createGame/updateGame` + `AuditLogService` | 唯一索引与恢复；逻辑删除；全量覆盖；审计 before/after | 删一个平台，再用同编码新建，看 id 是否复用 |

**读代码的小技巧**：
- 永远从 `controller` 找到方法名，再全局搜这个方法名到 `ServiceImpl`，最后看它调了哪个 `Mapper` 方法，再去 XML 找 SQL。
- 看不懂某个前端字段，就在后端 VO 里搜同名字段，一眼能看出它从哪来。
- 看到 `LambdaQueryWrapper` 别慌：`.eq(字段, 值)` = `where 字段 = 值`，`.in` / `.ge` / `.orderByDesc` 同理。

## 8. 术语急救包（看到这些就别卡住）

1. **`@RestController`**：这个类的方法返回值直接变成 JSON。
2. **`@RequestMapping("/games")`**：这个类下所有接口都以 `/api/games` 开头（前缀 `/api` 来自配置文件）。
3. **`@PathVariable` / `@RequestParam` / `@RequestBody`**：参数在路径里 / 在 `?a=b` 里 / 在请求体 JSON 里。
4. **`@Valid`**：触发 DTO 上的 `@NotBlank/@Size/@Min` 校验，不合法直接 400，不会进业务代码。
5. **`@Transactional`**：方法里所有写库要么全成、要么全滚。
6. **`@TableLogic`**：`deleteById` 实际执行的是 `UPDATE ... SET deleted=1`；查询自动加 `deleted=0`。
7. **`selectCount(...) > 0`**：就是"存不存在"。
8. **`Map.of("name", "该游戏已存在")`**：字段级错误，前端 `e.errors` 拿到后显示在对应输入框下。
9. **`ThreadLocal`**：一条请求一个口袋，请求结束必须清空，否则线程复用时上一个人的身份会漏给下一个人。
10. **`@Scheduled(cron=...)`**：定时任务，`0 0 4 * * ?` = 每天 4:00。
11. **`BigDecimal`**：金额专用类型，永远不要用 `double` 算钱。
12. **`LineStyle.width=0`**：ECharts 里"这个平台只有一个点，画点不画线"的技巧。
13. **`computed` / `watch`（Vue）**：派生值 / 监听变化后重新请求。
14. **Pinia store**：跨页面的全局状态（token、当前用户）。
15. **`non_null`**：`application.yml` 里配的，返回 JSON 时把 null 字段直接不输出，前端就不会收到一堆 `null`。

| 1 | **汇率没有自动刷新**，只有 3 条 seed | 上美元/港币平台后价格会一直按旧汇率算 |
| 2 | **官方史低全站为空**（2 条挂在已删平台） | 前端"史低"虚线没有，`type=2` 提醒也建不了 |
| 3 | **锁区风险全站为 0**（2 条挂在已删平台） | 详情页永远"无锁区风险" |
| 4 | **Epic 的 `external_id` 全 NULL** | Epic 采集 `total=0`，永远无价 |
| 5 | **小黑盒/杉果/steampy 无采集器** | 只能手动录入，采集日志写"暂无可用采集器" |
| 6 | **待确认队列无通知** | 有异常价进队，管理员不进页面就不知道 |
| 7 | **采集无并发锁** | 两个人同时点 / 定时与手动重叠，可能撞唯一索引 |
| 8 | **审计只写不读** | 想查操作记录只能开 SQL 客户端 |
| 9 | 没有游戏删除、没有历史价删除/编辑、没有通知清理 | 数据只能加不能减 |
| 10 | 链接模板不校验 URL 协议 | `javascript:` 可入库 |
| 11 | 前端只在 localStorage 存 token；无 refresh token | XSS 风险 + 120 分钟必须重登 |
| 12 | `listAll` 平台列表 N+1 查询（每平台 2 次 count） | 平台多了会慢，当前无感 |

## 10. 一句话记住整个项目

**一张 `price_record` 表定义"什么是有效价格"，所有页面都按同一口径读它；采集和手动录入是两条写入路径，写入前都要过"校验 → 汇率 → 归档 → 插入"；用户侧的一切（收藏、提醒、通知）都是围绕这条价格链加的外壳。**
